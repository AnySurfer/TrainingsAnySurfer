# Het project ophalen, installeren en bijwerken

Deze handleiding legt uit hoe je met de repository [AnySurfer/TrainingsAnySurfer](https://github.com/AnySurfer/TrainingsAnySurfer) werkt. Installeer eerst Node.js en Git volgens de handleiding met vereisten.

**Gebruik de eerste keer `git clone`** om het project en de geschiedenis te downloaden. **Gebruik daarna `git pull`** in je lokale kopie om updates op te halen. Je hoeft de repository niet opnieuw te klonen.

## 1. De tools controleren

Open Terminal op macOS of Git Bash op Windows. Controleer of elke opdracht een versienummer toont:

```sh
node --version
npm --version
git --version
```

Volgens `package.json` vereist het project Node.js **22.12.0 of nieuwer**. Het bestand `.nvmrc` vermeldt ook een referentieversie. Gebruik je al nvm op macOS, voer dan `nvm install` en daarna `nvm use` uit in de projectmap om die versie te gebruiken.

## 2. Het project voor de eerste keer downloaden

Ga naar de map waarin je je projecten wilt bewaren. Bijvoorbeeld, als je persoonlijke map een map `Documents` bevat:

```sh
cd ~/Documents
git clone https://github.com/AnySurfer/TrainingsAnySurfer.git
cd TrainingsAnySurfer
```

`git clone` maakt de map `TrainingsAnySurfer` aan. Met `cd` ga je naar die map. Voer de opdrachten van de volgende stappen uit in deze map, naast `package.json` en `astro.config.mjs`.

Vraagt GitHub om je aan te melden, gebruik dan het account met toegang tot de repository en volg de instructies van je referentiebeheerder. “Repository not found” kan wijzen op een verkeerd adres of ontbrekende toegang.

Open de map vervolgens in je editor. Met Visual Studio Code, als de opdracht `code` beschikbaar is:

```sh
code .
```

Gebruik anders **Bestand → Map openen** in de editor en selecteer `TrainingsAnySurfer`.

## 3. Afhankelijkheden installeren

Voer dit uit in de hoofdmap van het project:

```sh
npm ci
```

Deze opdracht installeert de afhankelijkheden uit `package-lock.json`, waaronder Astro en Reveal.js. Ze maakt de map `node_modules/` aan en vervangt de inhoud als die al bestaat. Wacht tot de installatie klaar is.

Gebruik `npm ci` om een projectkopie te installeren of de afhankelijkheden weer in overeenstemming met het lockbestand te brengen. Een nieuwe afhankelijkheid bewust toevoegen doe je apart met `npm install pakketnaam`.

## 4. De ontwikkelsite starten

Volgens de projectafspraken start je Astro op de achtergrond:

```sh
npm run astro -- dev --background
```

Open het adres dat de opdracht toont in je browser. De gebruikelijke poort is `4321`, maar Astro kan een andere kiezen als die bezet is.

Het adres terugvinden en de servermeldingen lezen:

```sh
npm run astro -- dev status
npm run astro -- dev logs
```

Open op dat adres `/docs?lang=nl` om de Nederlandstalige documentatie te lezen. Bij poort `4321` is dat bijvoorbeeld `http://localhost:4321/docs?lang=nl`.

De server volgt de bronbestanden en vernieuwt de pagina's na wijzigingen. Stoppen doe je met:

```sh
npm run astro -- dev stop
```

## 5. Updates ophalen met git pull

Is het project al geïnstalleerd, open dan een terminal **in je map `TrainingsAnySurfer`**. Controleer de huidige branch en je lokale wijzigingen:

```sh
git status
git branch --show-current
```

Heb je bestanden gewijzigd, bewaar je werk dan eerst: maak een commit op je werkbranch of zet de wijzigingen tijdelijk opzij met `git stash push -u -m "Werk voor update"`. De optie `-u` neemt nieuwe, nog niet gevolgde bestanden mee, maar geen genegeerde bestanden. Verwijder je wijzigingen niet om een update af te dwingen.

Werk de hoofdbranch bij nadat je je werk hebt bewaard:

```sh
npm run astro -- dev stop
git switch main
git pull --ff-only origin main
npm ci
npm run astro -- dev --background
```

Draait er geen server, sla de stopopdracht dan over. `git switch main` selecteert de hoofdbranch. `git pull --ff-only origin main` haalt updates op en werkt je lokale branch bij als er geen merge nodig is. `npm ci` installeert de afhankelijkheden voor de opgehaalde versie opnieuw.

Heb je `git stash` gebruikt, keer dan terug naar je werkbranch en herstel je wijzigingen met `git stash pop`. Als dezelfde regels zijn gewijzigd, moet je mogelijk conflicten oplossen.

**Weigert Git de pull omdat de branches uiteenlopen**, stop dan en bekijk de geschiedenis met de projectbeheerder. Voer geen geforceerde reset uit: die kan lokaal werk verwijderen.

## 6. De productieversie controleren

Bouw de site en bekijk het resultaat:

```sh
npm run build
npm run preview
```

De build maakt de bestanden in `dist/` aan. Open het adres dat de previewopdracht toont. Deze opdracht blijft actief in de terminal; stop ze met **Ctrl+C**.

De pagina's onder `/docs` zijn alleen voor ontwikkeling en zijn niet beschikbaar in deze preview. Voer na nieuwe bronwijzigingen opnieuw `npm run build` uit om de productieversie bij te werken.

## Veelvoorkomende problemen

| Melding of symptoom                                                      | Wat controleren?                                                                                                                  |
| ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| `node`, `npm` of `git` niet gevonden                                     | Volg de vereisten en sluit en heropen de terminal.                                                                                |
| `not a git repository`                                                   | Ga naar de map `TrainingsAnySurfer` die bij het klonen is aangemaakt.                                                             |
| npm vindt `package.json` niet                                            | Voer de opdracht uit in de hoofdmap van het project.                                                                              |
| `npm ci` meldt een ongeschikte Node.js-versie                            | Vergelijk de vereiste in `package.json` met `node --version`.                                                                     |
| `npm ci` meldt een verschil tussen `package.json` en `package-lock.json` | Controleer of beide bestanden uit dezelfde projectversie komen; laat het lockbestand corrigeren in plaats van het te verwijderen. |
| De browser toont de site niet                                            | Gebruik het exacte adres uit `dev status` en bekijk `dev logs`.                                                                   |
| De pull meldt `Already up to date`                                       | Je lokale branch bevat al de nieuwste wijzigingen van de opgehaalde branch.                                                       |

Ga verder met **Het AnySurfer-project begrijpen** via de link naar de volgende handleiding om meer te leren over pagina's, componenten, layouts en mappen.
