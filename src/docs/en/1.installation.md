# Get, install and update the project

This guide explains how to work with the [AnySurfer/TrainingsAnySurfer](https://github.com/AnySurfer/TrainingsAnySurfer) repository. Start by installing Node.js and Git using the prerequisites guide.

**Use `git clone` the first time** to download the project and its history. **Use `git pull` afterwards**, inside your local copy, to retrieve updates. You do not need to clone the repository again.

## 1. Check your tools

On macOS, open Terminal; on Windows, open Git Bash. Check that each command displays a version:

```sh
node --version
npm --version
git --version
```

The project requires Node.js **22.12.0 or later**, according to `package.json`. The `.nvmrc` file also specifies a reference version. If you already use nvm on macOS, run `nvm install`, then `nvm use` inside the project folder to use that version.

## 2. Download the project for the first time

Open the folder where you want to keep your projects. For example, if your home folder contains a `Documents` folder:

```sh
cd ~/Documents
git clone https://github.com/AnySurfer/TrainingsAnySurfer.git
cd TrainingsAnySurfer
```

`git clone` creates the `TrainingsAnySurfer` folder. `cd` moves you into it. Run the commands in the following steps from this folder, alongside `package.json` and `astro.config.mjs`.

If GitHub asks you to sign in, use the account with access to the repository and follow your credential manager's instructions. “Repository not found” may indicate an incorrect address or missing access.

Next, open the folder in your editor. With Visual Studio Code, if the `code` command is available:

```sh
code .
```

Otherwise, use **File → Open Folder** in your editor and select `TrainingsAnySurfer`.

## 3. Install dependencies

From the project root:

```sh
npm ci
```

This installs the dependencies specified in `package-lock.json`, including Astro and Reveal.js. It creates `node_modules/` and replaces its contents if it already exists. Wait for installation to finish before continuing.

Use `npm ci` to install a project copy or bring its dependencies into line with the lockfile. Adding a new dependency intentionally is a separate operation using `npm install package-name`.

## 4. Start the development site

The project requires Astro to run in the background:

```sh
npm run astro -- dev --background
```

Open the address printed by the command in your browser. The usual port is `4321`, but Astro may choose another one if that port is busy.

To find the address and read the server messages:

```sh
npm run astro -- dev status
npm run astro -- dev logs
```

At that address, open `/docs?lang=en` to read the documentation in English. For example, on port `4321`, open `http://localhost:4321/docs?lang=en`.

The server watches source files and refreshes pages after changes. To stop it:

```sh
npm run astro -- dev stop
```

## 5. Get updates with git pull

Once the project is installed, open a terminal **inside your `TrainingsAnySurfer` folder**. Check the current branch and your local changes:

```sh
git status
git branch --show-current
```

If you have edited files, save your work before continuing: commit it on your working branch or temporarily set it aside with `git stash push -u -m "Work before update"`. The `-u` option includes new untracked files, but not ignored files. Do not delete your changes to force an update.

To update the main branch after saving your work:

```sh
npm run astro -- dev stop
git switch main
git pull --ff-only origin main
npm ci
npm run astro -- dev --background
```

If no server is running, skip the stop command. `git switch main` selects the main branch. `git pull --ff-only origin main` retrieves its updates and advances your local branch if no merge is needed. `npm ci` reinstalls the dependencies for the retrieved version.

If you used `git stash`, return to the branch you were working on, then restore your changes with `git stash pop`. You may need to resolve conflicts if the same lines have changed.

**If Git refuses the pull because the branches have diverged**, stop and review the history with the project maintainer. Do not use a forced reset: it could remove local work.

## 6. Check the production version

To build the site and inspect the result:

```sh
npm run build
npm run preview
```

The build generates files in `dist/`. Open the address printed by the preview command. This command stays active in the terminal; use **Ctrl+C** to stop it.

The `/docs` pages are development-only and are not available in this preview. After changing source files again, rerun `npm run build` to update the production version.

## Common problems

| Message or symptom                                                         | What to check                                                                                                 |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `node`, `npm` or `git` not found                                           | Follow the prerequisites, then close and reopen your terminal.                                                |
| `not a git repository`                                                     | Move into the `TrainingsAnySurfer` folder created by cloning.                                                 |
| npm cannot find `package.json`                                             | Run the command from the project root.                                                                        |
| `npm ci` reports an incompatible Node.js version                           | Compare the requirement in `package.json` with `node --version`.                                              |
| `npm ci` reports a mismatch between `package.json` and `package-lock.json` | Check that both files come from the same project version; have the lockfile corrected instead of deleting it. |
| The browser does not display the site                                      | Use the exact address from `dev status`, then read `dev logs`.                                                |
| The pull says `Already up to date`                                         | Your local branch already contains the latest changes from the retrieved branch.                              |

To learn about pages, components, layouts and directories, continue with **Understanding the AnySurfer project** using the next-guide link.
