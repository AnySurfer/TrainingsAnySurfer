# Récupérer, installer et mettre à jour le projet

Ce guide explique comment travailler sur le dépôt [AnySurfer/TrainingsAnySurfer](https://github.com/AnySurfer/TrainingsAnySurfer). Commencez par installer Node.js et Git en suivant le guide des prérequis.

**La première fois, utilisez `git clone`** pour télécharger le projet et son historique. **Les fois suivantes, utilisez `git pull`** dans votre copie locale pour récupérer les mises à jour. Il n’est pas nécessaire de cloner à nouveau le dépôt.

## 1. Vérifier les outils

Sur macOS, ouvrez Terminal ; sur Windows, ouvrez Git Bash. Vérifiez que les commandes suivantes affichent une version :

```sh
node --version
npm --version
git --version
```

Le projet exige Node.js **22.12.0 ou plus récent**, selon `package.json`. Le fichier `.nvmrc` indique également une version de référence. Si vous utilisez déjà nvm sur macOS, vous pouvez exécuter `nvm install`, puis `nvm use` depuis le dossier du projet pour utiliser cette version.

## 2. Télécharger le projet la première fois

Placez-vous dans le dossier où vous souhaitez ranger vos projets. Par exemple, si vous avez un dossier `Documents` dans votre dossier personnel :

```sh
cd ~/Documents
git clone https://github.com/AnySurfer/TrainingsAnySurfer.git
cd TrainingsAnySurfer
```

`git clone` crée le dossier `TrainingsAnySurfer`. La commande `cd` vous place à l’intérieur. Les commandes des étapes suivantes doivent être exécutées dans ce dossier, à côté de `package.json` et de `astro.config.mjs`.

Si GitHub demande une authentification, utilisez le compte qui dispose de l’accès au dépôt et suivez la procédure proposée par votre gestionnaire d’identifiants. Un message « Repository not found » peut signaler une adresse incorrecte ou un accès manquant.

Ouvrez ensuite le dossier dans votre éditeur. Avec Visual Studio Code, si la commande `code` est disponible :

```sh
code .
```

Sinon, utilisez **Fichier → Ouvrir un dossier** dans l’éditeur et sélectionnez `TrainingsAnySurfer`.

## 3. Installer les dépendances

À la racine du projet :

```sh
npm ci
```

Cette commande installe les dépendances prévues par `package-lock.json`, notamment Astro et Reveal.js. Elle crée le dossier `node_modules/` et remplace son contenu s’il existe déjà. Attendez la fin de l’installation avant de continuer.

Utilisez `npm ci` pour installer une copie du projet ou la remettre en conformité avec le fichier de verrouillage. L’ajout volontaire d’une nouvelle dépendance se fait séparément avec `npm install nom-du-paquet`.

## 4. Lancer le site en développement

Le projet demande de démarrer Astro en arrière-plan :

```sh
npm run astro -- dev --background
```

Ouvrez l’adresse affichée par la commande dans votre navigateur. Le port habituel est `4321`, mais Astro peut en choisir un autre si ce port est occupé.

Pour retrouver l’adresse et consulter les messages du serveur :

```sh
npm run astro -- dev status
npm run astro -- dev logs
```

À cette adresse, ouvrez `/docs` pour lire la documentation. Par exemple, si le serveur utilise le port `4321`, ouvrez `http://localhost:4321/docs`.

Le serveur surveille les sources et actualise les pages après vos modifications. Pour l’arrêter :

```sh
npm run astro -- dev stop
```

## 5. Récupérer les mises à jour avec git pull

Lorsque le projet est déjà installé, ouvrez un terminal **dans votre dossier `TrainingsAnySurfer`**. Vérifiez la branche courante et vos modifications locales :

```sh
git status
git branch --show-current
```

Si vous avez modifié des fichiers, conservez votre travail avant de continuer : faites un commit sur votre branche de travail ou mettez temporairement les modifications de côté avec `git stash push -u -m "Travail avant mise à jour"`. L’option `-u` inclut les nouveaux fichiers non suivis, mais pas les fichiers ignorés. Ne supprimez pas vos changements pour forcer la mise à jour.

Pour mettre à jour la branche principale, une fois votre travail sauvegardé :

```sh
npm run astro -- dev stop
git switch main
git pull --ff-only origin main
npm ci
npm run astro -- dev --background
```

Si aucun serveur ne tourne, passez simplement la commande d’arrêt. `git switch main` sélectionne la branche principale. `git pull --ff-only origin main` récupère ses nouveautés et avance votre branche locale si cela ne nécessite pas de fusion. `npm ci` réinstalle les dépendances correspondant à la version récupérée.

Si vous aviez utilisé `git stash`, revenez sur la branche où vous travailliez, puis restaurez vos modifications avec `git stash pop`. Cette restauration peut demander de résoudre des conflits si les mêmes lignes ont changé.

**Si Git refuse le pull parce que les branches ont divergé**, arrêtez-vous et examinez l’historique avec la personne qui maintient le projet. Ne lancez pas de commande de réinitialisation forcée : elle pourrait supprimer du travail local.

## 6. Vérifier la version de production

Pour construire le site et examiner le résultat :

```sh
npm run build
npm run preview
```

La construction génère les fichiers dans `dist/`. Ouvrez l’adresse affichée par la prévisualisation. Cette commande reste active dans le terminal ; utilisez **Ctrl+C** pour l’arrêter.

Les pages `/docs` sont réservées au développement et ne sont pas disponibles dans cette prévisualisation. Après une nouvelle modification des sources, relancez `npm run build` pour actualiser la version de production.

## Problèmes fréquents

| Message ou symptôme                                                       | Que vérifier ?                                                                                                                            |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `node`, `npm` ou `git` introuvable                                        | Reprendre les prérequis, puis fermer et rouvrir le terminal.                                                                              |
| `not a git repository`                                                    | Se placer dans le dossier `TrainingsAnySurfer`, créé par le clonage.                                                                      |
| npm ne trouve pas `package.json`                                          | Exécuter la commande à la racine du projet.                                                                                               |
| `npm ci` signale une incompatibilité de version de Node.js                | Vérifier la version exigée dans `package.json` et celle indiquée par `node --version`.                                                    |
| `npm ci` signale un désaccord entre `package.json` et `package-lock.json` | Vérifier que les deux fichiers viennent de la même version du projet ; faire corriger le fichier de verrouillage plutôt que le supprimer. |
| Le navigateur n’affiche pas le site                                       | Utiliser l’adresse exacte de `dev status`, puis consulter `dev logs`.                                                                     |
| Le pull indique `Already up to date`                                      | La branche locale possède déjà les dernières modifications de la branche récupérée.                                                       |

Pour comprendre ensuite les pages, composants, layouts et répertoires, passez au guide **Comprendre le projet AnySurfer** via le lien suivant.
