# Understanding the AnySurfer project

This project produces AnySurfer training materials: presentations, printable syllabuses and resource pages in French, Dutch and English. It uses **Astro** to assemble pages and **Reveal.js** for presentations.

This guide describes the current repository structure.

## From source file to web page

A page chooses a layout and assembles components. For example:

```text
src/pages/fr/intro/index.astro        → URL /fr/intro/
  ├── src/layouts/LayoutSlides.astro  → HTML document, styles, Reveal.js
  └── src/components/fr/intro/…       → slide content
```

During development, Astro transforms source files when you visit a page and refreshes the browser after changes. `npm run build` generates the static site in `dist/`. The browser receives HTML, CSS, images and the scripts needed for interactions.

Code inside a component's `---` block runs in Astro. JavaScript inside a `<script>` block can run in the browser: this is how Reveal.js is initialized.

| `src/components/fr/`, `en/`, `nl/` | Slide content organized by language and training topic.                                |
| `src/components/ui/`               | Reusable elements: header, footer, presentation container, contents, etc.              |
| `src/layouts/`                     | Shared structures for regular pages, slides and syllabuses.                            |
| `src/assets/img/`                  | Images imported into components.                                                       |
| `src/assets/css/`                  | Shared stylesheets, themes and print styles.                                           |
| `src/assets/script/`               | Site scripts, including presentation visual effects.                                   |
| `src/assets/tech/`                 | Other technical project resources.                                                     |
| `src/data/`                        | JSON files: training catalogue, articles, tools and resources.                         |
| `src/i18n/`                        | Available languages, interface translations and language selection helpers.            |
| `src/utils/`                       | Shared helpers, including navigation and syllabus chapters.                            |
| `src/dev/`                         | Working pages exposed by the configuration only during development.                    |
| `src/docs/`                        | Contributor documentation in Markdown; this folder does not create URLs automatically. |
| `public/`                          | Files copied unchanged to the site root, such as `robots.txt`.                         |
| `.github/workflows/deploy.yml`     | Automatic build and deployment to GitHub Pages.                                        |
| `.astro/`                          | Generated Astro and integration files, including auto-import declarations.             |
| `dist/`                            | Production build output. Edit the sources, then rebuild.                               |
| `node_modules/`                    | Dependencies installed by npm.                                                         |

Main configuration files:

- `src/content.config.ts` defines the documentation collection, its loader and metadata schema.
- `astro.config.mjs` configures development routes, auto-imports, languages and deployment URLs.
- `package.json` defines dependencies and npm commands; `package-lock.json` locks installed versions.
- `tsconfig.json` enables TypeScript rules and import aliases.
- `.prettierrc.json` and `.prettierignore` configure formatting.

## File-based routing

**File-based routing** means that a file's path inside `src/pages/` defines the page address. `src/pages` and the `.astro` extension disappear from the URL. `index.astro` is the index page of its folder. See the [official Astro routing guide](https://docs.astro.build/en/guides/routing/).

Existing files and their paths with `base: '/'` are shown below. The i18n checks may reject `/fr/` paths with the current configuration; see the language section.

| File                                | URL                              |
| ----------------------------------- | -------------------------------- |
| `src/pages/index.astro`             | `/`                              |
| `src/pages/fr/index.astro`          | `/fr/`                           |
| `src/pages/fr/intro/index.astro`    | `/fr/intro/`                     |
| `src/pages/fr/intro/syllabus.astro` | `/fr/intro/syllabus/`            |
| `src/pages/fr/training/intro.astro` | `/fr/training/intro/`            |
| `src/pages/nl/intro/index.astro`    | `/nl/intro/`                     |
| `src/pages/404.astro`               | Error page for missing addresses |

`/fr/intro/` contains the presentation; `/fr/training/intro/` contains the training resources. They are separate pages.

### Add a regular page

For example, create `src/pages/fr/bonjour.astro`:

```astro
---
import Layout from '@layouts/Layout.astro'
---

<Layout title="Bonjour" lang="fr">
  <h1>Bonjour</h1>
  <p>My new page.</p>
</Layout>
```

### Excluded files and injected routes

A name starting with `_` excludes a file or folder from automatic routing. `src/pages/_autoplay-slides.astro` therefore does not become a public page solely through its location.

#### Further reading

See the official [Astro documentation](https://docs.astro.build/en/basics/project-structure/).

## Astro components

An `.astro` component has a preparation section between `---` markers, followed by an HTML template. It can receive parameters, called **props**, through `Astro.props`.

Example component at `src/components/fr/demo/Message.astro`:

```astro
---
interface Props {
  title: string
}
const { title } = Astro.props
---

<section>
  <h1>{title}</h1>
  <p>The slide content.</p>
  <aside class="notes">Notes for the presenter.</aside>
</section>
```

A page can import it and use `<Message title="Welcome" />`. A component has no URL of its own and can be reused across pages. See [Astro components](https://docs.astro.build/en/basics/astro-components/).

### Project-specific auto-imports

`astro.config.mjs` finds all `.astro` files under `src/components/` and registers them with `unplugin-auto-import`. Component names are formed from their paths, capitalizing each segment:

| File                                             | Name usable in a page               |
| ------------------------------------------------ | ----------------------------------- |
| `src/components/fr/intro/Accessibility.astro`    | `<FrIntroAccessibility />`          |
| `src/components/fr/personas/Nina.astro`          | `<FrPersonasNina />`                |
| `src/components/fr/demo/Message.astro` (example) | `<FrDemoMessage title="Welcome" />` |

Path separators, dots, spaces, hyphens and underscores separate words. A name beginning with a digit gets a leading `_`. Two files producing the same name cause a configuration error.

During development, a watcher rebuilds this list after additions, deletions and renames. Editor declarations are generated in `.astro/auto-imports.d.ts`.

This applies to components under `src/components/`. Layouts, Markdown and data files are imported explicitly.

### Import aliases

`tsconfig.json` defines these shortcuts:

| Alias          | Directory         |
| -------------- | ----------------- |
| `@components/` | `src/components/` |
| `@layouts/`    | `src/layouts/`    |
| `@assets/`     | `src/assets/`     |
| `@data/`       | `src/data/`       |

For example, `import Layout from '@layouts/LayoutSlides.astro'` avoids calculating a relative path such as `../../../layouts/LayoutSlides.astro`.

## Layouts and presentations

A **layout** provides a page's shared structure. Its `<slot />` indicates where to insert the content placed between its tags.

| Layout                  | Use                                                                            |
| ----------------------- | ------------------------------------------------------------------------------ |
| `LayoutDocs.astro`      | Documentation navigation, language links and a white reading surface.          |
| `Layout.astro`          | Regular pages with navigation, header and footer; used for training resources. |
| `LayoutSlides.astro`    | Reveal.js presentations with styles, navigation and notes.                     |
| `LayoutSlideAuto.astro` | Looping presentation that advances automatically every 20 seconds.             |
| `LayoutSyllabus.astro`  | Continuous document with contents, visible notes and printing.                 |

A presentation page assembles components in the desired order:

```astro
---
import Layout from '@layouts/LayoutSlides.astro'
---

<Layout title="Introduction" lang="fr">
  <FrIntroAccessibility />
  <FrIntroWho />
</Layout>
```

Reveal.js displays `<section>` elements as slides; nested sections allow vertical navigation. `<aside class="notes">` contains presenter notes.

The syllabus reuses content components inside `LayoutSyllabus`. This layout adjusts heading levels, prepares the contents and replaces embedded videos with links. To edit a shared slide, edit its component. To change slide order or selection, check **both pages**, presentation and syllabus: their lists are currently defined separately for the introduction.

## Languages

`src/i18n/config.ts` declares `fr`, `en` and `nl`, with French as the default. `prefixDefaultLocale` is absent, so Astro uses its default behavior without a prefix for French. Training pages in other languages use `/en/` and `/nl/`.

Responsibilities are split as follows:

- `src/pages/fr/`, `en/`, `nl/` define page URLs by language.
- `src/components/fr/`, `en/`, `nl/` contain the corresponding teaching content.
- `src/i18n/ui.ts` contains site interface translations.
- `src/i18n/utils.ts` provides `useTranslations(lang)` and supported-language selection.
- `src/i18n/client.ts` helps translate the interface in the browser.
- `src/i18n/docs.ts` contains documentation interface translations.

Creating a French page does not create English and Dutch versions automatically. The `/` home page is special: in development, it can use the preferred language received by Astro; the production build remains static and also adapts its display in the browser.

## Images, styles and data

### Images and public files

Images in `src/assets/` are imported into components. For example:

```astro
---
import Jim from '@assets/img/jim.png'
---

<img src={Jim.src} width={Jim.width} height={Jim.height} alt="Jim" />
```

`public/robots.txt` is served at `/robots.txt` locally with `base: '/'`. It is copied unchanged during the build. `src/assets/` and `public/` therefore serve different purposes.

### Styles

Layouts import shared styles from `src/assets/css/`. Presentations also load Reveal.js styles and AnySurfer themes. A component's `<style>` block scopes styles to that component; changes to shared stylesheets can affect many pages. See the [Astro styling guide](https://docs.astro.build/en/guides/styling/).

### JSON data

`src/data/training-pages.json` is used for the training catalogue on the home page. `*-training-resources.json` files group training resources. For example, `src/pages/fr/training/intro.astro` imports `intro-training-resources.json` to display articles, applications and bookmarks.

Adding a JSON entry does not create a route: a corresponding page in `src/pages/` is also required.

## Documentation in development

The `docs` **Content Collection**, declared in `src/content.config.ts`, loads Markdown from `src/docs/` with the `glob()` loader. Its Zod schema validates metadata and provides TypeScript types. `src/dev/docs.astro` uses `getCollection('docs')` for navigation and `render()` for the chosen guide. See the [Content Collections guide](https://docs.astro.build/en/guides/content-collections/).

A single `/docs/[...slug]` route is injected in development. `slug` selects a guide; without it, `/docs` displays the index.

| Local URL                | Content                             |
| ------------------------ | ----------------------------------- |
| `/docs?lang=en`          | English documentation index         |
| `/docs/en/prerequisites` | Installation and prerequisites      |
| `/docs/en/installation`  | Get, install and update the project |
| `/docs/en/projet`        | Understanding the project           |

Each guide starts with YAML metadata, called **frontmatter**. The title and translation key are required:

```yaml
---
title: My new guide
slug: en/my-guide
lang: en
translationKey: my-guide
order: 3
---
```

To add a guide, create a `.md` file in `src/docs/`. It appears in its language's navigation at `/docs/en/my-guide` without another configuration entry or Astro page. Do not add `layout`: the shared page already provides it.

`slug` is optional: without it, the loader generates a normalized ID from the file path. An explicit slug becomes the entry's `id` and its path below `/docs/`. Subdirectories are supported. IDs must be unique; Astro reports collisions. Explicit slugs accept unaccented letters, digits, hyphens, underscores and internal dots in segments separated by `/`. The schema requires a non-empty `title` and validates `order` as an integer (default 0). Navigation sorts by `order`, then by ID.

Each translation has its own Markdown file. `lang` selects `fr`, `en` or `nl` (default `fr`), and the required `translationKey` connects translations of the same guide. Use the same key in all three versions, with different slugs such as `my-guide`, `en/my-guide` and `nl/my-guide`. Each key must be unique within its language.

The language switcher opens the corresponding translation while keeping the current guide. Navigation and previous/next links show only the selected language. Interface text comes from `src/i18n/docs.ts`, and HTML `lang` follows the document language. The index is at `/docs` for French, `/docs?lang=en` for English and `/docs?lang=nl` for Dutch. These paths stay under the single development route, independently of training-page i18n prefixes.

`LayoutDocs.astro` supplies the guide menu, white reading surface and pagination. On small screens, the menu moves above the content. A missing slug returns HTTP 404. `[...slug]` covers the index and nested guide paths; `prerender: false` selects content per development request without `getStaticPaths()`.

These routes are absent from `npm run build` and `npm run preview`, because injection is limited to `dev`.

## Commands and deployment

### Build a GitHub Pages-compatible link

The site may be published below a repository prefix. Existing pages use this convention:

```astro
---
const base = import.meta.env.BASE_URL.replace(/\/$/, '')
---

<a href={`${base}/fr/intro/`}>Introduction presentation</a>
```

This produces `/fr/intro/` at the root or, for example, `/repository-name/fr/intro/` when `base` contains the repository name.

Run commands from the project root. `package.json` requires Node.js **22.12.0 or later**.

| Command                       | Effect                                         |
| ----------------------------- | ---------------------------------------------- |
| `npm ci`                      | Install dependencies from `package-lock.json`. |
| `npm run astro -- dev status` | Show server status and address.                |
| `npm run astro -- dev logs`   | Read server logs.                              |
| `npm run astro -- dev stop`   | Stop the development server.                   |
| `npm run build`               | Generate the production site in `dist/`.       |
| `npm run preview`             | Serve the latest production build locally.     |
| `npm run format:check`        | Check formatting with Prettier.                |
| `npm run format`              | Reformat supported project files.              |

The usual port is `4321`. If busy, Astro may choose another port: use the address printed at startup or by `dev status`.

`npm run preview` does not rebuild sources. Rerun `npm run build` before checking a changed production version.

`.github/workflows/deploy.yml` builds and publishes to GitHub Pages on a push to `main` or a manual run on that branch. It sets `DEPLOY_TARGET=github-pages`. The configuration uses `GITHUB_REPOSITORY` to calculate `site` and `base`. Outside this mode, it accepts `SITE_URL` and `BASE_PATH`.
