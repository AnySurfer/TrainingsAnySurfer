ARIA-attributen wijzigen semantiek

  • Vooral bedoeld om ontbrekende semantiek toe te voegen aan de accessibility tree.
  • Kunnen ook semantische informatie veranderen.
  • Kunnen ook semantiek verwijderen.

1. Rol

  • In accessibility tree heeft elke component een rol nodig.
  • Als er een HTML-element bestaat met de gewenste rol: gebruik dat dan.
  • Semantische elementen vullen de accessibility tree in.
  • Ook het role-attribuut bepaalt de rol van een component in de accessibility tree.

Goed voorbeeld: tabs widget

  • HTML heeft geen semantisch element voor tabpanelen.
  • Het zijn div's en die hebben geen rol in accessibility tree.
  • role="tabpanel" vult de accessibility tree aan. 
<div id="tabpanel2" role="tabpanel">

ARIA wint!

  • Elke component kan in accessibility tree slechts 1 rol hebben.
  • Als component al een impliciete rol had, zal het role-attribuut die overschrijven.

Slecht voorbeeld

<div id="main_nav">
<ul role="navigation">
  • Het ul element geeft de component de rol Lijst.
  • role="navigation" verandert de rol naar Navigatie
  • Het is geen lijst meer.
  • Screenreader kondigt navigatiegebied aan maar geen lijst.

Beter

<div id="main_nav" role="navigation">
<ul>

Of:

<nav id="main_nav">
<ul>

Het role-attribuut

  • Wijzigt semantische informatie enkel in de accessibility tree.
  • Verandert niets aan:
    • Gedrag
    • Eigenschappen
    • Uitzicht

Voorbeeld

<div role="button">
Search
</div>

Nog geen knop

  • Screenreader zegt "knop search" in plaats van "search".
  • Maar:
    • Is niet bereikbaar met tabtoets
    • Ziet er niet uit als een knop
    • Erop klikken, doet niets

Waarden voor role-attribuut

  • Liggen vast, verzin niet zelf
  • Overlap met HTML-elementen
  • Aanvulling op HTML
  • role="presentation"
  • role="application"

Overlap met HTML-elementen

  • role="navigation" versus <nav>
  • role="button" versus <button>
  • role="checkbox" versus <input type="checkbox">
  • ...

Aanvulling op HTML

  • tablist, tab, tabpanel
  • progressbar
  • spinbutton
  • ...

Sommige roles dienen niet voor wat hun naam doet vermoeden

  • Gebruik geen role="menu" voor een reeks links: WAI-ARIA menus, and why you should handle them with great care
  • Gebruik geen role="grid" voor een sorteerbare tabel
  • Gebruik geen role="treeview" voor een uitklapmenu
  • ARIA: The Cause of, and Solution to, All Our Accessibility Problems

Special: Role="presentation"

  • Verwijdert de rol van de component uit de accessibility tree.
  • Neemt dus semantiek weg.
  • Alternatief: role="none"

Voorbeeld

<h2 role="presentation">Over ons</h2>

Wordt in accessibility tree:

<div>Over ons</div>

Maar het blijft er als een kop uitzien.

Wanneer gebruiken?

  • Legacy code met bvb opmaaktabellen
  • Als compromis in semantische discussies

Special: role="application"

  • De component met deze rol wordt in accessibility tree een toepassing.
  • In die component valt alle functionaliteit van assistive technologies weg.
  • Je moet alles zelf opnieuw programmeren.
  • Je moet aan de gebruiker uitleggen hoe je toepassing werkt.

Praktijk

  • Zeer zelden gebruiken
  • Op de kleinst mogelijke component.
  • Met role="document" kan je een component binnen de toepassing weer bruikbaar maken met standaard screenreadercommando's.

Samengevat

  • Role attribuut kan ontbrekende info toevoegen aan accessibility tree
  • Opgelet met het overschrijven van de rol.
  • role="presentation" verwijdert de semantische rol.
  • Role verandert niets aan uitzicht en functionaliteit.

2. Naam

  • In accessibility tree heeft elke component ook een naam nodig.
  • HTML-elementen vullen die impliciet in: linktekst, alt-tekst, value van knop enz.
  • Kan ook expliciet met aria-label en aria-labelledby.

Impliciet

<a href="/contact">Neem contact op</a>

<img src="logo.png" alt="AnySurfer" />

<label for="fname">Uw voornaam</label>
<input type="text" id="fname" />

Expliciet met aria-label

<form name="search_website">
<input type="text" name="search" aria-label="Zoekterm" />
<input type="submit" value="Zoeken" />
</form>

Aria-label

  • Waarde van attribuut = tekst
  • Als component nog geen naam had, wordt die toegevoegd
  • Als component al een naam had, wordt die vervangen

Slecht voorbeeld

Overschrijf bestaande naam niet:

<a href="w3.org"
aria-label="World Wide Web Consortium">
W3C
</a>

Wat is het probleem?

  • Op het scherm staat "W3C"
  • Screenreader leest: [link] "World Wide Web Consortium"
  • Gebruiker dicteersoftware zegt: [klik] "W3C", maar er gebeurt niets

Accessibility tree

Aria-labelledby

  • Waarde van attribuut = id-waarde van tekst die elders staat
  • Meerdere verwijzingen mogelijk, gescheiden door spaties

Voorbeeld

<a role="tab" id="tab1">Maandag</a>
<a role="tab" id="tab2">Dinsdag</a>
<div id="tabpanel1" role="tabpanel" aria-labelledby="tab1"></div>
<div id="tabpanel2" role="tabpanel" aria-labelledby="tab2"></div>

Aandachtspunten aria-label(ledby)

  • Werkt enkel met component die rol heeft, dus niet op div of span.
  • Enkel in accessibility tree, niet zichtbaar op het scherm.
  • Vergeet niet te vertalen.
  • Overdrijf niet.
  • Herhaal de rol niet.

Herhaal de rol niet

<button aria-label="Zoekknop">
<a href="facebook.com" aria-label="Link naar Facebook"></a>
<main aria-label="hoofdinhoud">
<nav aria-label="hoofdnavigatie">

Beter

<button aria-label="Zoeken">
<a href="facebook.com" aria-label="Facebook"></a>
<main>
<nav> of <nav aria-label="hoofd">

3. Status en eigenschappen

  • Component heeft in accessibility tree ook status en eigenschappen.
  • Ook die kan je toevoegen of wijzigen met ARIA-attributen.
  • How to toggle ARIA values with JavaScript

Voorbeelden

  • aria-expanded="true" of aria-expanded="false"
  • aria-checked="true" of aria-checked="false"
  • aria-hidden="true" of aria-hidden="false"
  • En nog veel meer

Gebruik

  • Enkel bij roles die het toestaan
  • Vb. aria-pressed enkel bij component die de rol button heeft.
  • En dan enkel als component ook echt een toggle button is.
  • Vb. Vet, Ondertitels

In de juiste context

  • aria-selected, aria-checked, aria-pressed en aria-current lijken op elkaar maar zijn verschillend.
  • Dit artikel legt de verschillen uit.

Aria-hidden

  • aria-hidden="true" verwijdert component en al zijn inhoud uit accessibility tree
  • Verdwijnt voor gebruikers van assistive technologies, maar blijft zichtbaar op het scherm.
  • Niet gebruiken voor interactieve elementen

Voorbeeld

<div aria-hidden="true">
Deze tekst staat op het scherm maar hoor je niet met een screenreader.
</div>
<a href="#" aria-hidden="true">
Deze link werkt niet voor gebruikers van asssistive technologies.
</a>

4. Beschrijving

  • Component kan in accessibility tree ook een beschrijving hebben
  • Staat los van naam, geen "gevaar" van overschrijven
  • Aria-describedby=""
  • Waarde = een of meerdere id-verwijzingen

Voorbeeld

<label for="email">E-mailadres</label>
<input type="text" name="email" id="email" aria-describedby="error17" />
<p class="error" id="error17">Het ingevulde e-mailadres is ongeldig.</p>

Screenreader leest

Als invoerveld focus krijgt met tabtoets:

E-mailadres, invoerveld, Het ingevulde e-mailadres is ongeldig.

Gebruik

  • Zelden
  • Enkel op component die semantische rol heeft
  • Enkel op componenten die focus krijgen, zoals links, knoppen of formuliervelden.

Samenvatting

  • Gebruik geen ARIA als je hetzelfde kan met een HTML-element
  • ARIA-attributen beïnvloeden enkel de accessibility tree; Ze voegen geen functionaliteit toe
  • Geen ARIA is beter dan verkeerde of overbodige

Oefening

<ul role="list">

<div class="sectiontitle" role="heading" aria-level="2">

<div role="checkbox" aria-checked="true">

<article role="presentation">

<iframe name="google_ads" aria-hidden="true">
