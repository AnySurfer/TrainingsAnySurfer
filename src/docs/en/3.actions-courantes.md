# Common tasks

This guide covers everyday work on slides, decks, syllabuses and training resource pages. Paths refer to the current repository; `demo` files and `demo.*` keys are **examples to create**, not existing features.

## Choose the right file

| Task                                    | Main source                            | Also check                                      |
| --------------------------------------- | -------------------------------------- | ----------------------------------------------- |
| Correct a slide                         | `src/components/{lang}/…/*.astro`      | Every deck and syllabus reusing it              |
| Add, remove or move a slide             | `src/pages/{lang}/{deck}/index.astro`  | `syllabus.astro`, chapters and anchors          |
| Change site interface text              | `src/i18n/ui.ts`                       | All three languages and calls to `t()`          |
| Change documentation interface text     | `src/i18n/docs.ts`                     | All three languages and `LayoutDocs.astro`      |
| Update resource links                   | The JSON imported by the training page | Sections and links written in the `.astro` page |
| Add a deck to the catalogue             | `src/components/ui/TrainingList.astro` | Existing slide and syllabus pages               |
| Add training resources to the catalogue | `src/data/training-pages.json`         | A page under `src/pages/{lang}/training/`       |

The French examples follow the existing `/fr/` structure. The current i18n configuration may reject these paths. Read the language section of **Understanding the project** before publishing a new path. These examples do not require changing the global configuration.

## Edit a slide

1. Open the deck, such as `src/pages/fr/intro/index.astro`.
2. Find the slide tag, such as `<FrIntroWho />`.
3. Open its component: `src/components/fr/intro/Who.astro`.
4. Edit text, links, images or notes inside `<aside class="notes">`.
5. Check all uses and the affected translations.

Find uses from the terminal:

```sh
rg -n 'FrIntroWho' src/pages src/components
```

Auto-import names come from paths: `fr/intro/Who.astro` becomes `FrIntroWho`. A file under `src/components/` is not a page with its own URL.

**Shared content matters:** a component change appears everywhere it is used. For a course-specific variant, create a separate component or add an explicit prop. Also check manual imports and slides written directly in page files.

**Check:** no overflow during presentation, appropriate alternative text, current notes and correct rendering of the same content in the syllabus.

## Update a slide deck and its syllabus

Editing the content of a shared component propagates automatically. **Adding, removing or moving a component in the presentation does not automatically update the syllabus list.**

1. Change the selection and order in `src/pages/fr/intro/index.astro`.
2. Apply the same change to `src/pages/fr/intro/syllabus.astro`.
3. Leave presentation covers and instructions out of the syllabus when they do not help readers.
4. If `chapters` is defined, update its titles and order. Every `id` must target a section that actually exists.
5. Check `slidesHref`, internal links and other courses reusing the components.
6. Open both versions and check the contents, notes and print preview.

A slide inserted after `<FrIntroWho />` in the deck should appear at the same point in the syllabus's teaching content. A deleted slide must not remain in the printable document.

Without `chapters`, `LayoutSyllabus` can generate contents from sections. Maintain explicit chapter lists manually. Avoid duplicate IDs even though the layout removes some duplicates when rendering.

## Create a new slide deck

### 1. Prepare the content

Create `src/components/fr/demo/Content.astro`:

```astro
<section id="demo-objectifs">
  <h1>Objectifs de la formation</h1>
  <ul>
    <li>Comprendre le sujet.</li>
    <li>Mettre les conseils en pratique.</li>
  </ul>
  <aside class="notes">Présenter les objectifs et demander les attentes.</aside>
</section>
```

It becomes available as `<FrDemoContent />`. Grouping teaching content in a shared component reduces differences between the deck and syllabus. Do not include a page layout or an additional Reveal.js container inside it.

### 2. Create the presentation

Create `src/pages/fr/demo/index.astro`:

```astro
---
import Layout from '@layouts/LayoutSlides.astro'
---

<Layout title="Ma formation" lang="fr">
  <FrSharedInstructions />
  <FrSharedTitle title="Ma formation" />
  <FrDemoContent />
</Layout>
```

These examples retain French paths, text and locale settings to match the original repository example. For an English course, use `en` paths, `lang="en"` and corresponding English components and content.

### 3. Create the syllabus

Create `src/pages/fr/demo/syllabus.astro`:

```astro
---
import LayoutSyllabus from '@layouts/LayoutSyllabus.astro'
const base = import.meta.env.BASE_URL.replace(/\/$/, '')
---

<LayoutSyllabus title="Ma formation" lang="fr" slidesHref={`${base}/fr/demo/`}>
  <FrDemoContent />
</LayoutSyllabus>
```

Both pages use the same content. If you choose separate component lists instead, maintain them together after every change.

### 4. Add the deck to the catalogue

Add an object to the `trainings` array in `src/components/ui/TrainingList.astro`:

```ts
{
  slug: 'demo',
  fr: 'Ma formation',
}
```

Add `en` and `nl` only when their pages exist. This catalogue builds **both slide and syllabus links**: create both pages before adding an entry. It is separate from the training resource catalogue.

## Create or update a translation key

### Site interface

1. Open `src/i18n/ui.ts`.
2. Add the same key to `fr`, `en` and `nl`, translated in each language:

```ts
// In fr
'demo.resources': 'Ressources de la formation',
// In en
'demo.resources': 'Training resources',
// In nl
'demo.resources': 'Opleidingsmateriaal',
```

3. Use the key in a component:

```astro
---
import { useTranslations } from '../i18n/utils'
const t = useTranslations('en')
---

<h2>{t('demo.resources')}</h2>
```

Adapt the import path to the file location. For a shared component, obtain the language from props or `Astro.currentLocale` as appropriate.

To change wording, retain the key and update its values. Before renaming or deleting a key, find and update every call:

```sh
rg -n 'demo.resources' src
```

The helper has a runtime French fallback for missing or empty values, but this does not replace translations in all three languages or TypeScript checks. Training titles in `TrainingList.astro`, JSON and text written directly in pages are not automatically translated by `t()`.

### Documentation interface

Documentation labels use `src/i18n/docs.ts`, not `ui.ts`. Update the three `docsUi` objects and their uses in `LayoutDocs.astro` or `src/dev/docs.astro`. Translate guide content in the Markdown files.

## Update training resources

For the French introduction, `src/pages/fr/training/intro.astro` imports `src/data/intro-training-resources.json`.

1. Open the page and check **which JSON it imports**: names differ by course and language.
2. Edit `{ "href": "…", "label": "…" }` objects in the right list: `articles`, `applications` or `bookmarks` in this example.
3. Keep JSON valid: double quotes, commas between objects, no trailing comma.
4. For a slide link, heading or new section, also check the page HTML: not everything comes from JSON.
5. Test links and labels on the rendered page. Check other pages importing the same file.

Example article to add to an existing list:

```json
{
  "href": "https://www.anysurfer.be/fr/documentation",
  "label": "AnySurfer documentation"
}
```

`bookmarks` may contain JavaScript. Preserve JSON escaping and test bookmarklets on a suitable test page. When changing only a label, avoid modifying its code.

## Create a new training page

A training page groups course materials and can link to multiple decks. Creating the page does not create those decks.

1. Choose a unique path, for example `demo` in French.
2. Create `src/pages/fr/training/demo.astro`, using a similar existing page as a model.
3. Adapt the layout title, visible title, language, anchors, slide links and relevant sections.
4. If needed, create `src/data/demo-training-resources.json` and update the import. Keep the keys expected by the chosen model; the introduction model needs at least:

```json
{
  "articles": [],
  "applications": [],
  "bookmarks": []
}
```

5. Fill the lists and hide or remove empty sections when they are not useful.
6. Add an entry to `src/data/training-pages.json`:

```json
{
  "lang": "fr",
  "path": "demo",
  "title": "Ma formation",
  "featured": true
}
```

`path` is relative to `/fr/training/`: omit `/fr/training/`, `.astro` and full URLs. `featured` is optional. When featured courses exist, the home page uses them, with a maximum of four per language. The training index shows all entries in its language.

7. Check the training index and home page. The JSON feeds `TrainingResourcesIndex.astro` and the home page but **does not generate the page**.
8. If the course has a new deck, add its `TrainingList.astro` entry and syllabus separately.
9. Create other languages' pages and data separately, then add their catalogue entries. Do not list translations before they exist.

## Add an image or replace a file

Put imported images in `src/assets/img/`, then update the import, `src`, dimensions and alternative text. Use `alt=""` for decorative images. Find all uses before replacing a shared image.

Use `public/` for a file served unchanged. `public/example.pdf` is available at `${base}/example.pdf`, without `public` in the URL. Files in `Input/` are not automatically published. Update links after renaming files and check the downloaded version.

## Rename or delete an item

Search `src/` for the component name, path and slug before changing the file. Update automatic or manual imports, both catalogues, training-page links, the syllabus and chapter anchors. Renaming a component changes its auto-import name; renaming a page can change its public URL.

If a previously shared URL changes, provide a deployment-compatible redirect or retain a transition page. Check old URLs as well as new ones.

## Add a documentation page

Create three Markdown files, for example `src/docs/4.my-guide.md`, `src/docs/en/4.my-guide.md` and `src/docs/nl/4.my-guide.md`. Use translated titles and metadata adapted to each language:

```yaml
---
title: My guide
slug: en/my-guide
lang: en
translationKey: my-guide
order: 4
---
```

For French, use `lang: fr` and `slug: my-guide`; for Dutch, use `lang: nl` and `slug: nl/my-guide`. Keep the same `translationKey` and `order`. The collection adds the pages to navigation automatically; no extra route is needed. Do not add `layout` to Markdown.

## Check before sharing

- Check the presentation, syllabus, notes and print preview after content changes.
- Check links, chapters, images, keyboard use and visible focus; review affected languages.
- Check the deck catalogue, training catalogue and home page separately.
- Account for `import.meta.env.BASE_URL` in internal links, following existing models.
- Format only edited files to avoid unrelated changes, then run `npm run build` if production sources changed.
- Review `git diff` and `git diff --check` before sharing.

```sh
npm run astro -- dev status
npm run astro -- dev logs
npm run build
npm run preview
```

If the server is stopped, start it with `npm run astro -- dev --background`. `preview` shows the latest build without development-only documentation pages. A successful build does not guarantee working links or consistency between a deck and its syllabus: these checks are still necessary.
