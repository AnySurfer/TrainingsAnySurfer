# Actions courantes

Ce guide décrit les opérations habituelles sur les slides, diaporamas, syllabus et pages de ressources. Les chemins correspondent au dépôt actuel ; les fichiers `demo` et les clés `demo.*` sont des **exemples à créer**, pas des éléments déjà présents.

## Choisir le bon fichier

| Action                                    | Source principale                      | À vérifier aussi                                   |
| ----------------------------------------- | -------------------------------------- | -------------------------------------------------- |
| Corriger une slide                        | `src/components/{lang}/…/*.astro`      | Tous les diaporamas et syllabus qui la réutilisent |
| Ajouter, retirer ou déplacer une slide    | `src/pages/{lang}/{deck}/index.astro`  | `syllabus.astro`, chapitres et ancres              |
| Changer un libellé de l’interface du site | `src/i18n/ui.ts`                       | Les trois langues et les appels à `t()`            |
| Changer un libellé de la documentation    | `src/i18n/docs.ts`                     | Les trois langues et `LayoutDocs.astro`            |
| Modifier des liens de ressources          | Le JSON importé par la page training   | Sections et liens codés dans la page `.astro`      |
| Ajouter un diaporama au catalogue         | `src/components/ui/TrainingList.astro` | Page de slides et syllabus existants               |
| Ajouter un training au catalogue          | `src/data/training-pages.json`         | Page sous `src/pages/{lang}/training/`             |

Les exemples français reprennent l’organisation actuelle sous `/fr/`. Avec la configuration i18n actuelle, ces chemins peuvent être refusés. Consulter la section sur les langues du guide **Comprendre le projet** avant de publier un nouveau chemin. Les exemples n’impliquent pas de changer la configuration globale.

## Modifier une slide

1. Ouvrir le diaporama, par exemple `src/pages/fr/intro/index.astro`.
2. Repérer la balise de la slide, par exemple `<FrIntroWho />`.
3. Ouvrir le composant correspondant : `src/components/fr/intro/Who.astro`.
4. Modifier son texte, ses liens, ses images ou ses notes dans `<aside class="notes">`.
5. Vérifier tous ses usages et les traductions concernées.

Pour retrouver ses utilisations dans le terminal :

```sh
rg -n 'FrIntroWho' src/pages src/components
```

Les noms des imports automatiques viennent du chemin : `fr/intro/Who.astro` donne `FrIntroWho`. Un fichier sous `src/components/` n’est pas une page avec une URL propre.

**Attention au contenu partagé :** une correction dans un composant se répercute partout où il est utilisé. Pour une variante réservée à une formation, créer un composant distinct ou ajouter une prop explicite. Vérifier aussi les éventuels imports manuels et les slides écrites directement dans une page.

**Vérifier :** pas de débordement en présentation, texte alternatif pertinent, notes à jour et rendu correct du même contenu dans le syllabus.

## Mettre à jour un slidedeck et son syllabus

Une modification du contenu d’un composant partagé se répercute automatiquement. **Un ajout, retrait ou déplacement de composant dans la présentation ne modifie pas automatiquement la liste du syllabus.**

1. Modifier la sélection et l’ordre dans `src/pages/fr/intro/index.astro`.
2. Reporter le changement dans `src/pages/fr/intro/syllabus.astro`.
3. Garder les couvertures et instructions de présentation hors du syllabus si elles ne sont pas utiles à la lecture.
4. Si `chapters` est défini, adapter ses titres et son ordre. Chaque `id` doit viser une section réellement présente.
5. Vérifier `slidesHref`, les liens internes et les autres formations qui réutilisent les composants.
6. Ouvrir les deux versions et contrôler le sommaire, les notes et l’aperçu avant impression.

Une slide ajoutée après `<FrIntroWho />` dans la présentation doit apparaître au même endroit dans le contenu pédagogique du syllabus. À l’inverse, une slide supprimée ne doit pas rester dans le document imprimable.

Sans liste `chapters`, `LayoutSyllabus` peut générer le sommaire à partir des sections. Avec une liste explicite, la maintenir manuellement. Éviter les `id` dupliqués, même si le layout retire certains doublons lors du rendu.

## Créer un nouveau slidedeck

### 1. Préparer le contenu

Créer `src/components/fr/demo/Content.astro` :

```astro
<section id="demo-objectifs">
  <h1>Objectifs de la formation</h1>
  <ul>
    <li>Comprendre le sujet.</li>
    <li>Mettre les conseils en pratique.</li>
  </ul>
  <aside class="notes">Présenter les objectifs et demander les attentes.</aside>
</section>
```

Ce composant sera utilisable sous le nom `<FrDemoContent />`. Un composant partagé regroupant le contenu pédagogique permet de limiter les différences entre slides et syllabus. Il ne doit pas contenir de layout de page ni de conteneur Reveal.js supplémentaire.

### 2. Créer la présentation

Créer `src/pages/fr/demo/index.astro` :

```astro
---
import Layout from '@layouts/LayoutSlides.astro'
---

<Layout title="Ma formation" lang="fr">
  <FrSharedInstructions />
  <FrSharedTitle title="Ma formation" />
  <FrDemoContent />
</Layout>
```

### 3. Créer le syllabus

Créer `src/pages/fr/demo/syllabus.astro` :

```astro
---
import LayoutSyllabus from '@layouts/LayoutSyllabus.astro'
const base = import.meta.env.BASE_URL.replace(/\/$/, '')
---

<LayoutSyllabus title="Ma formation" lang="fr" slidesHref={`${base}/fr/demo/`}>
  <FrDemoContent />
</LayoutSyllabus>
```

Les deux pages utilisent le même contenu. Si vous choisissez plutôt deux listes de composants séparées, les maintenir ensemble à chaque modification.

### 4. Ajouter le diaporama au catalogue

Dans le tableau `trainings` de `src/components/ui/TrainingList.astro`, ajouter un objet comme :

```ts
{
  slug: 'demo',
  fr: 'Ma formation',
}
```

Ajouter `en` et `nl` seulement lorsque les pages correspondantes existent. Ce catalogue construit **à la fois les liens vers les slides et vers les syllabus** : créer les deux pages avant de l’enrichir. Il est distinct du catalogue des ressources training.

## Créer ou modifier une clé de traduction

### Interface du site

1. Ouvrir `src/i18n/ui.ts`.
2. Ajouter la même clé dans les objets `fr`, `en` et `nl`, avec une valeur traduite dans chaque langue. Exemple :

```ts
// Dans fr
'demo.resources': 'Ressources de la formation',
// Dans en
'demo.resources': 'Training resources',
// Dans nl
'demo.resources': 'Opleidingsmateriaal',
```

3. Utiliser la clé dans un composant :

```astro
---
import { useTranslations } from '../i18n/utils'
const t = useTranslations('fr')
---

<h2>{t('demo.resources')}</h2>
```

Adapter le chemin d’import à l’emplacement du fichier et choisir la langue à partir des props ou de `Astro.currentLocale` lorsque le composant est partagé.

Pour modifier seulement une formulation, garder la clé et changer les valeurs. Pour renommer ou supprimer une clé, retrouver et adapter tous ses appels :

```sh
rg -n 'demo.resources' src
```

Le helper prévoit un repli vers le français pour une valeur absente ou vide à l’exécution, mais cela ne remplace pas les trois traductions ni leur vérification TypeScript. Les titres de formation dans `TrainingList.astro`, les JSON et certains textes écrits directement dans les pages ne sont pas automatiquement traduits par `t()`.

### Interface de la documentation

Les libellés des guides utilisent `src/i18n/docs.ts`, pas `ui.ts`. Modifier les trois objets de `docsUi`, puis les usages dans `LayoutDocs.astro` ou `src/dev/docs.astro`. Les textes des guides se traduisent dans les fichiers Markdown.

## Mettre à jour les ressources training

Pour l’introduction française, la page est `src/pages/fr/training/intro.astro`. Elle importe `src/data/intro-training-resources.json`.

1. Ouvrir la page et vérifier **quel JSON elle importe** : le nom varie selon la formation et la langue.
2. Modifier les objets `{ "href": "…", "label": "…" }` dans la bonne liste : `articles`, `applications` ou `bookmarks` dans cet exemple.
3. Garder un JSON valide : guillemets doubles, virgules entre les objets, aucune virgule après le dernier élément.
4. Pour un lien de diaporama, un titre ou une nouvelle section, vérifier aussi le HTML de la page : tout n’est pas dans le JSON.
5. Tester les liens et leur libellé sur la page rendue. Vérifier les autres pages important le même fichier.

Exemple d’article à ajouter dans la liste existante :

```json
{
  "href": "https://www.anysurfer.be/fr/documentation",
  "label": "Documentation AnySurfer"
}
```

Les `bookmarks` peuvent contenir du JavaScript. Préserver les échappements JSON et tester le signet sur une page de test appropriée. Pour remplacer seulement son libellé, éviter de modifier son code.

## Créer un nouveau training

Un training est une page qui rassemble les supports d’une formation ; il peut lier plusieurs diaporamas. Créer sa page ne crée pas ces diaporamas.

1. Choisir un chemin unique, par exemple `demo` pour le français.
2. Créer `src/pages/fr/training/demo.astro` en prenant une page proche comme modèle.
3. Adapter le titre du layout, le titre visible, la langue, les ancres, les liens vers les diaporamas et les sections utiles.
4. Si nécessaire, créer `src/data/demo-training-resources.json`, puis adapter l’import dans la page. Reprendre les clés attendues par le modèle ; pour le modèle d’introduction, la base minimale est :

```json
{
  "articles": [],
  "applications": [],
  "bookmarks": []
}
```

5. Remplir les listes et masquer ou retirer les sections vides si elles ne sont pas utiles.
6. Ajouter cette entrée dans `src/data/training-pages.json` :

```json
{
  "lang": "fr",
  "path": "demo",
  "title": "Ma formation",
  "featured": true
}
```

`path` est relatif à `/fr/training/` : ne pas y inclure `/fr/training/`, `.astro` ou une URL complète. `featured` est facultatif ; l’accueil utilise les formations mises en avant lorsqu’il y en a, avec un maximum de quatre par langue. L’index training affiche toutes les entrées de sa langue.

7. Vérifier l’index training et l’accueil. Le JSON alimente `TrainingResourcesIndex.astro` et l’accueil, mais **ne génère pas la page**.
8. Si un nouveau diaporama accompagne le training, ajouter séparément son entrée dans `TrainingList.astro` et son syllabus.
9. Créer séparément les pages et données des autres langues, puis leurs entrées de catalogue. Ne pas afficher une traduction qui n’existe pas encore.

## Ajouter une image ou remplacer un fichier

Mettre les images importées dans `src/assets/img/`, puis adapter l’import, `src`, les dimensions et le texte alternatif. Pour une image décorative, utiliser `alt=""`. Chercher les usages avant de remplacer une image partagée.

Pour un fichier servi tel quel, utiliser `public/`. Un fichier `public/exemple.pdf` est accessible sous `${base}/exemple.pdf`, sans `public` dans l’URL. Les fichiers de `Input/` ne sont pas automatiquement publiés. Mettre à jour les liens après un changement de nom et vérifier la version téléchargée.

## Renommer ou supprimer un élément

Chercher le nom du composant, le chemin et le slug dans `src/` avant de modifier le fichier. Adapter les imports automatiques ou manuels, les deux catalogues, les liens depuis les trainings, le syllabus et les ancres de chapitres. Un renommage de composant modifie son nom d’import automatique ; un renommage de page peut modifier son URL publique.

Si une URL déjà partagée change, prévoir une redirection adaptée au déploiement ou conserver une page de transition. Vérifier aussi les anciennes URL, pas seulement les nouvelles.

## Ajouter une page de documentation

Créer trois Markdown, par exemple `src/docs/4.mon-guide.md`, `src/docs/en/4.mon-guide.md` et `src/docs/nl/4.mon-guide.md`. Utiliser des titres traduits et les métadonnées suivantes, adaptées à chaque langue :

```yaml
---
title: Mon guide
slug: mon-guide
lang: fr
translationKey: mon-guide
order: 4
---
```

Pour les autres versions, utiliser `lang: en` et `slug: en/mon-guide`, puis `lang: nl` et `slug: nl/mon-guide`. Garder le même `translationKey` et le même `order`. La collection ajoute automatiquement les pages au menu ; aucune route supplémentaire n’est nécessaire. Ne pas ajouter de champ `layout` au Markdown.

## Vérifier avant de partager

- Vérifier la présentation, le syllabus, les notes et l’aperçu d’impression après une modification de contenu.
- Contrôler les liens, les chapitres, les images, le clavier et le focus visible ; vérifier les trois langues concernées.
- Vérifier séparément le catalogue des diaporamas, le catalogue training et l’accueil.
- Tenir compte de `import.meta.env.BASE_URL` pour les liens internes, comme dans les modèles existants.
- Formater uniquement les fichiers modifiés pour éviter des changements sans rapport, puis lancer `npm run build` si les sources de production sont touchées.
- Relire `git diff` et `git diff --check` avant de partager les modifications.

```sh
npm run astro -- dev status
npm run astro -- dev logs
npm run build
npm run preview
```

Si le serveur est arrêté, le démarrer avec `npm run astro -- dev --background`. `preview` montre la dernière construction, sans les pages de documentation réservées au développement. Une construction réussie ne garantit ni l’absence de liens cassés ni la cohérence entre présentation et syllabus : ces contrôles restent nécessaires.
