# Het AnySurfer-project begrijpen

Dit project maakt het AnySurfer-opleidingsmateriaal: presentaties, afdrukbare syllabussen en pagina's met hulpmiddelen, in het Frans, Nederlands en Engels. Het gebruikt **Astro** om pagina's samen te stellen en **Reveal.js** voor de presentaties.

Deze handleiding beschrijft de huidige structuur van de repository. Begin met de handleiding met vereisten om de tools te installeren.

## Van bronbestand naar webpagina

Een pagina kiest een layout en voegt componenten samen. Bijvoorbeeld:

```text
src/pages/fr/intro/index.astro        → URL /fr/intro/
  ├── src/layouts/LayoutSlides.astro  → HTML-document, stijlen, Reveal.js
  └── src/components/fr/intro/…       → inhoud van de dia's
```

Tijdens ontwikkeling verwerkt Astro de bronnen wanneer je een pagina bezoekt en vernieuwt het de browser na wijzigingen. Met `npm run build` wordt de statische site in `dist/` gegenereerd. De browser ontvangt HTML, CSS, afbeeldingen en scripts voor de interacties.

Code tussen de `---`-markeringen van een component wordt door Astro uitgevoerd. JavaScript in een `<script>`-blok kan in de browser worden uitgevoerd: zo wordt Reveal.js geïnitialiseerd.

## Routering op basis van bestanden

**File-based routing** betekent dat het pad van een bestand in `src/pages/` het pagina-adres bepaalt. `src/pages` en de extensie `.astro` verdwijnen uit de URL. Een bestand `index.astro` is de startpagina van zijn map. Zie de [officiële Astro-handleiding over routering](https://docs.astro.build/en/guides/routing/).

Hieronder staan bestaande bestanden en hun paden met `base: '/'`. De i18n-controle kan met de huidige configuratie paden onder `/fr/` weigeren; zie het onderdeel over talen.

| Bestand                             | URL                                  |
| ----------------------------------- | ------------------------------------ |
| `src/pages/index.astro`             | `/`                                  |
| `src/pages/fr/index.astro`          | `/fr/`                               |
| `src/pages/fr/intro/index.astro`    | `/fr/intro/`                         |
| `src/pages/fr/intro/syllabus.astro` | `/fr/intro/syllabus/`                |
| `src/pages/fr/training/intro.astro` | `/fr/training/intro/`                |
| `src/pages/nl/intro/index.astro`    | `/nl/intro/`                         |
| `src/pages/404.astro`               | Foutpagina voor ontbrekende adressen |

`/fr/intro/` bevat de presentatie; `/fr/training/intro/` bevat de opleidingsbronnen. Het zijn afzonderlijke pagina's.

### Een gewone pagina toevoegen

Maak bijvoorbeeld `src/pages/fr/bonjour.astro`:

```astro
---
import Layout from '@layouts/Layout.astro'
---

<Layout title="Bonjour" lang="fr">
  <h1>Bonjour</h1>
  <p>Mijn nieuwe pagina.</p>
</Layout>
```

Dit definieert `/fr/bonjour/`, maar de huidige i18n-controle kan het Franse voorvoegsel weigeren. Maak voor een nieuwe pagina in de standaardtaal liever `src/pages/bonjour.astro`: die krijgt de URL `/bonjour/`. Je hoeft geen extra route in `astro.config.mjs` te declareren. Voeg op een relevante pagina een link toe zodat bezoekers de pagina kunnen vinden.

### Uitgesloten bestanden en geïnjecteerde routes

Een naam die met `_` begint, sluit een bestand of map uit van automatische routering. `src/pages/_autoplay-slides.astro` wordt dus niet alleen door zijn locatie een publieke pagina.

Het project gebruikt ook `injectRoute()` in de integratie `development-pages` in `astro.config.mjs`. Die koppelt expliciet een URL aan een bestand buiten de gewone routering. Deze routes worden alleen geregistreerd als `command === 'dev'`.

### En dynamische routes?

Astro ondersteunt segmenten tussen vierkante haken, zoals `[slug].astro`, om meerdere pagina's met één sjabloon te maken. Bij statische generatie levert `getStaticPaths()` de te bouwen paden. Opleidingen gebruiken momenteel expliciete paginabestanden. De documentatie gebruikt een dynamische route die alleen tijdens ontwikkeling beschikbaar is, zoals hieronder beschreven.

## Astro-componenten

Een `.astro`-component bevat een voorbereidingsdeel tussen `---`-markeringen en daarna een HTML-sjabloon. Via `Astro.props` kan de component parameters ontvangen, ook **props** genoemd.

Voorbeeld in `src/components/fr/demo/Message.astro`:

```astro
---
interface Props {
  title: string
}
const { title } = Astro.props
---

<section>
  <h1>{title}</h1>
  <p>De inhoud van de dia.</p>
  <aside class="notes">Notities voor de presentator.</aside>
</section>
```

Een pagina kan de component importeren en `<Message title="Welkom" />` gebruiken. De component heeft geen eigen URL en kan op meerdere pagina's worden hergebruikt. Zie [Astro-componenten](https://docs.astro.build/en/basics/astro-components/).

### Automatische imports in dit project

`astro.config.mjs` zoekt alle `.astro`-bestanden onder `src/components/` en registreert ze met `unplugin-auto-import`. De componentnaam wordt afgeleid van het pad, met een hoofdletter aan het begin van elk segment:

| Bestand                                            | Naam op een pagina                 |
| -------------------------------------------------- | ---------------------------------- |
| `src/components/fr/intro/Accessibility.astro`      | `<FrIntroAccessibility />`         |
| `src/components/fr/personas/Nina.astro`            | `<FrPersonasNina />`               |
| `src/components/fr/demo/Message.astro` (voorbeeld) | `<FrDemoMessage title="Welkom" />` |

Padscheidingstekens, punten, spaties, koppeltekens en underscores scheiden de woorden. Begint de naam met een cijfer, dan komt er een `_` voor. Twee bestanden die dezelfde naam opleveren veroorzaken een configuratiefout.

Tijdens ontwikkeling wordt de lijst vernieuwd bij toevoegingen, verwijderingen en naamswijzigingen. Declaraties voor de editor worden aangemaakt in `.astro/auto-imports.d.ts`.

Dit geldt voor componenten onder `src/components/`. Layouts, Markdown- en gegevensbestanden worden expliciet geïmporteerd.

### Importaliassen

`tsconfig.json` definieert deze verkorte paden:

| Alias          | Map               |
| -------------- | ----------------- |
| `@components/` | `src/components/` |
| `@layouts/`    | `src/layouts/`    |
| `@assets/`     | `src/assets/`     |
| `@data/`       | `src/data/`       |

Met `import Layout from '@layouts/LayoutSlides.astro'` hoef je bijvoorbeeld geen relatief pad zoals `../../../layouts/LayoutSlides.astro` te berekenen.

## Layouts en presentaties

Een **layout** levert de gemeenschappelijke structuur van een pagina. `<slot />` geeft aan waar de inhoud tussen de componenttags wordt ingevoegd.

| Layout                  | Gebruik                                                                                |
| ----------------------- | -------------------------------------------------------------------------------------- |
| `LayoutDocs.astro`      | Documentatienavigatie, taallinks en een wit leesvlak.                                  |
| `Layout.astro`          | Gewone pagina's met navigatie, koptekst en voettekst; gebruikt voor opleidingsbronnen. |
| `LayoutSlides.astro`    | Reveal.js-presentaties met stijlen, navigatie en notities.                             |
| `LayoutSlideAuto.astro` | Presentatie in een lus die automatisch elke 20 seconden verdergaat.                    |
| `LayoutSyllabus.astro`  | Doorlopend document met inhoudsopgave, zichtbare notities en afdrukfunctie.            |

Een presentatiepagina voegt componenten in de gewenste volgorde samen:

```astro
---
import Layout from '@layouts/LayoutSlides.astro'
---

<Layout title="Introduction" lang="fr">
  <FrIntroAccessibility />
  <FrIntroWho />
</Layout>
```

Reveal.js toont `<section>`-elementen als dia's; geneste secties maken verticale navigatie mogelijk. `<aside class="notes">` bevat de presentatornotities.

De syllabus hergebruikt de inhoudscomponenten in `LayoutSyllabus`. Die layout past onder meer de kopniveaus aan, bereidt de inhoudsopgave voor en vervangt ingesloten video's door links. Wijzig de component om een gedeelde dia aan te passen. Controleer **beide pagina's**, presentatie en syllabus, als je de selectie of volgorde wijzigt: voor de introductie zijn de lijsten momenteel apart gedefinieerd.

## Talen

`src/i18n/config.ts` declareert `fr`, `en` en `nl`, met Frans als standaardtaal. `prefixDefaultLocale` ontbreekt: Astro gebruikt daardoor het standaardgedrag zonder voorvoegsel voor Frans. Opleidingspagina's in andere talen gebruiken `/en/` en `/nl/`.

**Bijzonderheid van de repository:** de bestaande Franse pagina's en veel links gebruiken nog `/fr/`. De huidige i18n-controle kan deze paden weigeren. Deze handleiding verplaatst die pagina's niet. Om de site gelijk te trekken, moeten de locaties en links worden aangepast aan Frans zonder voorvoegsel, of moet `routing: { prefixDefaultLocale: true }` in een aparte wijziging worden geactiveerd. Zie [meertalige routering in Astro](https://docs.astro.build/en/guides/internationalization/).

De verantwoordelijkheden zijn verdeeld:

- `src/pages/fr/`, `en/`, `nl/` bepalen de pagina-URL's per taal.
- `src/components/fr/`, `en/`, `nl/` bevatten de bijbehorende opleidingsinhoud.
- `src/i18n/ui.ts` bevat de interfacevertalingen van de site.
- `src/i18n/utils.ts` biedt onder meer `useTranslations(lang)` en de selectie van een ondersteunde taal.
- `src/i18n/client.ts` helpt de interface in de browser te vertalen.
- `src/i18n/docs.ts` bevat de interfacevertalingen van de documentatie.

Een Franse pagina maken genereert niet automatisch Engelse en Nederlandse versies. De startpagina `/` is bijzonder: tijdens ontwikkeling kan die de voorkeurstaal gebruiken die Astro ontvangt; de productiebuild blijft statisch en past de weergave ook in de browser aan.

## Afbeeldingen, stijlen en gegevens

### Afbeeldingen en publieke bestanden

Afbeeldingen in `src/assets/` worden in componenten geïmporteerd. Bijvoorbeeld:

```astro
---
import Jim from '@assets/img/jim.png'
---

<img src={Jim.src} width={Jim.width} height={Jim.height} alt="Jim" />
```

Stem de alternatieve tekst af op de functie van de afbeelding. Gebruik `alt=""` voor een decoratieve afbeelding.

`public/robots.txt` wordt lokaal aangeboden op `/robots.txt` met `base: '/'`. Het wordt bij de build ongewijzigd gekopieerd. `src/assets/` en `public/` dienen dus verschillende doelen.

### Stijlen

Layouts importeren gedeelde stijlen uit `src/assets/css/`. Presentaties laden ook de Reveal.js-stijlen en AnySurfer-thema's. Een `<style>`-blok in een component beperkt stijlen tot die component; een wijziging in een gedeelde stylesheet kan veel pagina's beïnvloeden. Zie de [Astro-handleiding over stijlen](https://docs.astro.build/en/guides/styling/).

### JSON-gegevens

`src/data/training-pages.json` wordt onder meer gebruikt voor de opleidingscatalogus op de startpagina. De bestanden `*-training-resources.json` groeperen opleidingsbronnen. Zo importeert `src/pages/fr/training/intro.astro` het bestand `intro-training-resources.json` om artikelen, toepassingen en bladwijzers te tonen.

Een JSON-vermelding toevoegen maakt geen route aan: er moet ook een bijbehorende pagina in `src/pages/` bestaan.

## Documentatie tijdens ontwikkeling

De **Content Collection** `docs`, gedeclareerd in `src/content.config.ts`, laadt Markdown uit `src/docs/` met de loader `glob()`. Het Zod-schema valideert metadata en levert TypeScript-typen. `src/dev/docs.astro` gebruikt `getCollection('docs')` voor de navigatie en `render()` voor de gekozen handleiding. Zie de [handleiding over Content Collections](https://docs.astro.build/en/guides/content-collections/).

Er wordt tijdens ontwikkeling één route `/docs/[...slug]` geïnjecteerd. `slug` kiest de handleiding; zonder slug toont `/docs` het overzicht.

| Lokale URL               | Inhoud                                        |
| ------------------------ | --------------------------------------------- |
| `/docs?lang=nl`          | Nederlandstalig documentatieoverzicht         |
| `/docs/nl/prerequisites` | Installatie en vereisten                      |
| `/docs/nl/installation`  | Het project ophalen, installeren en bijwerken |
| `/docs/nl/projet`        | Het project begrijpen                         |

Elke handleiding begint met YAML-metadata, ook **frontmatter** genoemd. De titel en vertaalsleutel zijn verplicht:

```yaml
---
title: Mijn nieuwe handleiding
slug: nl/mijn-handleiding
lang: nl
translationKey: mijn-handleiding
order: 3
---
```

Maak een `.md`-bestand in `src/docs/` om een handleiding toe te voegen. Ze verschijnt in het menu van haar taal op `/docs/nl/mijn-handleiding`, zonder extra configuratieregel of Astro-pagina. Voeg geen `layout` toe: de gedeelde pagina levert die al.

`slug` is optioneel: zonder slug maakt de loader een genormaliseerde ID op basis van het bestandspad. Een expliciete slug wordt de `id` van de vermelding en het pad onder `/docs/`. Submappen worden ondersteund. ID's moeten uniek zijn; Astro meldt dubbele waarden. Expliciete slugs accepteren letters zonder accenten, cijfers, koppeltekens, underscores en interne punten binnen segmenten, gescheiden door `/`. Het schema vereist een niet-lege `title` en valideert `order` als geheel getal (standaard 0). Het menu sorteert op `order` en daarna op ID.

Elke vertaling heeft een eigen Markdown-bestand. `lang` kiest `fr`, `en` of `nl` (standaard `fr`) en de verplichte `translationKey` koppelt vertalingen van dezelfde handleiding. Gebruik dezelfde sleutel in alle drie versies, met verschillende slugs zoals `mijn-handleiding`, `en/mijn-handleiding` en `nl/mijn-handleiding`. Elke sleutel moet per taal uniek zijn.

De taalwisselaar opent de bijbehorende vertaling van de huidige handleiding. Het menu en de vorige/volgende-links tonen alleen de gekozen taal. Interfaceteksten staan in `src/i18n/docs.ts`; het HTML-attribuut `lang` volgt de documenttaal. Het overzicht staat op `/docs` voor Frans, `/docs?lang=en` voor Engels en `/docs?lang=nl` voor Nederlands. Deze paden vallen onder de ene ontwikkelroute en staan los van de i18n-voorvoegsels van opleidingspagina's.

`LayoutDocs.astro` levert het menu, het witte leesvlak en de paginanavigatie. Op kleine schermen staat het menu boven de inhoud. Een onbekende slug levert HTTP 404 op. `[...slug]` omvat het overzicht en geneste handleidingpaden; met `prerender: false` wordt de inhoud tijdens ontwikkeling per aanvraag gekozen, zonder `getStaticPaths()`.

Deze routes ontbreken in `npm run build` en `npm run preview`, omdat ze alleen voor `dev` worden geïnjecteerd.

## Veelvoorkomende wijzigingen

### De tekst van een dia aanpassen

1. Open de opleidingspagina, bijvoorbeeld `src/pages/fr/intro/index.astro`.
2. Zoek de betreffende component, zoals `<FrIntroWho />`.
3. Wijzig `src/components/fr/intro/Who.astro`.
4. Controleer de presentatie en de syllabus die de component hergebruiken.

### Een opleiding toevoegen

Deze procedure volgt de bestaande structuur onder `/fr/`. Los de samenhang met de hierboven beschreven i18n-instelling op voordat je een nieuwe Franse opleiding publiceert.

1. Maak inhoudscomponenten in `src/components/fr/ma-formation/`.
2. Maak `src/pages/fr/ma-formation/index.astro` met `LayoutSlides` en voeg de componenten samen.
3. Maak indien nodig `src/pages/fr/ma-formation/syllabus.astro` met `LayoutSyllabus`.
4. Maak een bronnenpagina onder `src/pages/fr/training/` en indien nodig JSON-gegevens.
5. Werk de catalogi en relevante links bij, waaronder `src/data/training-pages.json` als de opleiding daarin moet verschijnen. Volg de structuur van een bestaande vermelding.
6. Maak andere taalversies apart.

### Een link voor GitHub Pages maken

De site kan onder een repositoryvoorvoegsel worden gepubliceerd. Bestaande pagina's gebruiken deze conventie:

```astro
---
const base = import.meta.env.BASE_URL.replace(/\/$/, '')
---

<a href={`${base}/fr/intro/`}>Introductiepresentatie</a>
```

Dit geeft `/fr/intro/` op het hoofdniveau of bijvoorbeeld `/repositorynaam/fr/intro/` als `base` de repositorynaam bevat.

## Opdrachten en publicatie

Voer de opdrachten uit in de hoofdmap van het project. `package.json` vereist Node.js **22.12.0 of nieuwer**.

| Opdracht                      | Effect                                                |
| ----------------------------- | ----------------------------------------------------- |
| `npm ci`                      | Afhankelijkheden uit `package-lock.json` installeren. |
| `npm run astro -- dev status` | Serverstatus en adres tonen.                          |
| `npm run astro -- dev logs`   | Serverlogboeken lezen.                                |
| `npm run astro -- dev stop`   | De ontwikkelserver stoppen.                           |
| `npm run build`               | De productiesite in `dist/` genereren.                |
| `npm run preview`             | De nieuwste productiebuild lokaal aanbieden.          |
| `npm run format:check`        | De opmaak met Prettier controleren.                   |
| `npm run format`              | Ondersteunde projectbestanden opnieuw opmaken.        |

De gebruikelijke poort is `4321`. Is die bezet, dan kan Astro een andere kiezen: gebruik het adres dat bij het starten of door `dev status` wordt getoond.

`npm run preview` bouwt de bronnen niet opnieuw. Voer eerst `npm run build` uit om een gewijzigde productieversie te controleren.

`.github/workflows/deploy.yml` bouwt en publiceert op GitHub Pages na een push naar `main` of een handmatige start op die branch. De workflow stelt `DEPLOY_TARGET=github-pages` in. De configuratie gebruikt `GITHUB_REPOSITORY` om `site` en `base` te berekenen. Buiten die modus accepteert ze `SITE_URL` en `BASE_PATH`.

## Problemen oplossen

| Symptoom                                                                | Controle                                                                                        |
| ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Een pagina geeft 404                                                    | Controleer het pad onder `src/pages/`, het taalvoorvoegsel en het serveradres.                  |
| Een bestand in `src/docs/` is niet via een URL te openen                | De map maakt geen routes aan; gebruik de collectie en de ontwikkelroute.                        |
| Het log meldt “No API Route handler exists” voor geïnjecteerde Markdown | Laat `injectRoute()` verwijzen naar een `.astro`-pagina die de Markdown weergeeft.              |
| Documentatie werkt tijdens ontwikkeling, maar niet in preview           | Dat is het verwachte gedrag van ontwikkelroutes.                                                |
| Een automatisch geïmporteerde component is onbekend                     | Controleer het pad, de gegenereerde naam, de logboeken en dubbele namen; herstart indien nodig. |
| Een wijziging ontbreekt in preview                                      | Bouw de site opnieuw en vernieuw de pagina.                                                     |
| Een link werkt lokaal, maar niet op GitHub Pages                        | Controleer of de link rekening houdt met `import.meta.env.BASE_URL`.                            |
| Een catalogusvermelding opent een 404                                   | Controleer of de doelpagina bestaat; JSON genereert geen pagina's.                              |

Bekijk vóór het delen van een wijziging de betrokken pagina's, controleer links en toetsenbordbediening en bouw de site als de wijziging gevolgen heeft voor productie.
