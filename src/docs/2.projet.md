# Comprendre le projet AnySurfer

Ce projet produit les supports de formation AnySurfer : présentations, syllabus imprimables et pages de ressources, en français, néerlandais et anglais. Il utilise **Astro** pour assembler les pages et **Reveal.js** pour les présentations.

Ce guide décrit l’organisation actuelle du dépôt.

## Du fichier source à la page web

Une page choisit un layout et assemble des composants. Par exemple :

```text
src/pages/fr/intro/index.astro        → URL /fr/intro/
  ├── src/layouts/LayoutSlides.astro  → document HTML, styles, Reveal.js
  └── src/components/fr/intro/…       → contenu des diapositives
```

En développement, Astro transforme les sources lorsque vous consultez une page et recharge le navigateur après les modifications. Avec `npm run build`, il génère le site statique dans `dist/`. Le navigateur reçoit du HTML, du CSS, des images et les scripts nécessaires aux interactions.

Le code placé dans le bloc `---` d’un composant est exécuté par Astro. Le JavaScript d’un bloc `<script>` peut, lui, s’exécuter dans le navigateur : c’est notamment ainsi que Reveal.js est initialisé.

| `src/components/ui/`               | Éléments réutilisables : en-tête, pied de page, conteneur de présentation, sommaire, etc.         |
| `src/layouts/`                     | Structures communes pour les pages classiques, slides et syllabus.                                |
| `src/assets/img/`                  | Images utilisées par les sources et importées dans les composants.                                |
| `src/assets/css/`                  | Feuilles de style communes, thèmes et styles d’impression.                                        |
| `src/assets/script/`               | Scripts du site, notamment les effets visuels des présentations.                                  |
| `src/assets/tech/`                 | Autres ressources techniques du projet.                                                           |
| `src/data/`                        | Fichiers JSON : catalogue des formations, articles, outils et ressources.                         |
| `src/i18n/`                        | Langues disponibles, traductions de l’interface et fonctions de sélection de langue.              |
| `src/utils/`                       | Fonctions partagées, par exemple pour la navigation et les chapitres des syllabus.                |
| `src/dev/`                         | Pages de travail exposées par la configuration uniquement en développement.                       |
| `src/docs/`                        | Documentation Markdown des contributeurs. Ce dossier ne crée aucune URL automatiquement.          |
| `public/`                          | Fichiers copiés tels quels à la racine du site, par exemple `robots.txt`.                         |
| `.github/workflows/deploy.yml`     | Construction et publication automatiques sur GitHub Pages.                                        |
| `.astro/`                          | Fichiers générés par Astro et par les intégrations, dont les déclarations d’imports automatiques. |
| `dist/`                            | Résultat de la construction pour la production. Modifier les sources, puis reconstruire.          |
| `node_modules/`                    | Dépendances installées par npm.                                                                   |

Les principaux fichiers à la racine :

- `src/content.config.ts` définit la collection de documentation, son chargement et son schéma de métadonnées.
- `astro.config.mjs` configure les routes de développement, les imports automatiques, les langues et les URL de déploiement.
- `package.json` définit les dépendances et les commandes npm ; `package-lock.json` fixe les versions installées.
- `tsconfig.json` active les règles TypeScript et les alias d’import.
- `.prettierrc.json` et `.prettierignore` règlent le formatage.

## Le routage basé sur les fichiers

Le **file-based routing** signifie que le chemin d’un fichier dans `src/pages/` définit l’adresse d’une page. Le nom `src/pages` disparaît de l’URL, ainsi que l’extension `.astro`. Un fichier `index.astro` représente la page d’accueil de son dossier. Voir le [guide officiel du routage Astro](https://docs.astro.build/en/guides/routing/).

Correspondance entre les fichiers présents et leurs chemins, avec `base: '/'`. Attention : le contrôle i18n peut refuser les chemins `/fr/` avec la configuration actuelle ; voir la section sur les langues :

| Fichier                             | URL                                          |
| ----------------------------------- | -------------------------------------------- |
| `src/pages/index.astro`             | `/`                                          |
| `src/pages/fr/index.astro`          | `/fr/`                                       |
| `src/pages/fr/intro/index.astro`    | `/fr/intro/`                                 |
| `src/pages/fr/intro/syllabus.astro` | `/fr/intro/syllabus/`                        |
| `src/pages/fr/training/intro.astro` | `/fr/training/intro/`                        |
| `src/pages/nl/intro/index.astro`    | `/nl/intro/`                                 |
| `src/pages/404.astro`               | Page d’erreur pour les adresses introuvables |

`/fr/intro/` contient la présentation ; `/fr/training/intro/` contient les ressources de formation. Ce sont deux pages distinctes.

### Ajouter une page ordinaire

Créer par exemple `src/pages/fr/bonjour.astro` :

```astro
---
import Layout from '@layouts/Layout.astro'
---

<Layout title="Bonjour" lang="fr">
  <h1>Bonjour</h1>
  <p>Ma nouvelle page.</p>
</Layout>
```

### Fichiers exclus et routes injectées

Un nom commençant par `_` exclut un fichier ou un dossier du routage automatique. Ainsi, `src/pages/_autoplay-slides.astro` ne devient pas une page publique par son seul emplacement.

#### Pour allez plus loin

Consultez la documentation officielle d'[Astro](https://docs.astro.build/en/basics/project-structure/)

## Les composants Astro

Un composant `.astro` contient une partie de préparation entre `---`, puis un modèle HTML. Il peut recevoir des paramètres, appelés **props**, via `Astro.props`.

Exemple d’un nouveau composant `src/components/fr/demo/Message.astro` :

```astro
---
interface Props {
  title: string
}

const { title } = Astro.props
---

<section>
  <h1>{title}</h1>
  <p>Le contenu de la diapositive.</p>
  <aside class="notes">Les notes destinées à la personne qui présente.</aside>
</section>
```

Une page peut importer ce composant, puis écrire `<Message title="Bienvenue" />`. Le composant ne possède pas d’URL propre et peut être utilisé dans plusieurs pages. Voir les [composants Astro](https://docs.astro.build/en/basics/astro-components/).

### Les imports automatiques propres au projet

`astro.config.mjs` recherche tous les fichiers `.astro` sous `src/components/` et les enregistre avec `unplugin-auto-import`. Le nom du composant est formé à partir du chemin, avec une majuscule au début de chaque segment :

| Fichier                                          | Nom utilisable dans une page          |
| ------------------------------------------------ | ------------------------------------- |
| `src/components/fr/intro/Accessibility.astro`    | `<FrIntroAccessibility />`            |
| `src/components/fr/personas/Nina.astro`          | `<FrPersonasNina />`                  |
| `src/components/fr/demo/Message.astro` (exemple) | `<FrDemoMessage title="Bienvenue" />` |

Les séparateurs de chemin, points, espaces, tirets et underscores séparent les mots. Un nom commençant par un chiffre reçoit un `_` initial. Deux fichiers produisant le même nom provoquent une erreur de configuration.

En développement, un mécanisme surveille les ajouts, suppressions et renommages pour reconstruire cette liste. Les déclarations pour l’éditeur sont générées dans `.astro/auto-imports.d.ts`.

Cette automatisation concerne les composants sous `src/components/`. Les layouts, fichiers Markdown et données sont importés explicitement.

### Les alias d’import

`tsconfig.json` définit ces raccourcis :

| Alias          | Répertoire        |
| -------------- | ----------------- |
| `@components/` | `src/components/` |
| `@layouts/`    | `src/layouts/`    |
| `@assets/`     | `src/assets/`     |
| `@data/`       | `src/data/`       |

Par exemple, `import Layout from '@layouts/LayoutSlides.astro'` évite de calculer un chemin relatif comme `../../../layouts/LayoutSlides.astro`.

## Les layouts et les présentations

Un **layout** est un composant qui fournit la structure commune d’une page. Son `<slot />` indique où insérer le contenu placé entre ses balises.

| Layout                  | Utilisation                                                                                            |
| ----------------------- | ------------------------------------------------------------------------------------------------------ |
| `LayoutDocs.astro`      | Documentation avec navigation des guides, liens vers les langues disponibles et fond blanc de lecture. |
| `Layout.astro`          | Pages classiques avec navigation, en-tête et pied de page ; utilisé pour les ressources de formation.  |
| `LayoutSlides.astro`    | Présentations Reveal.js, avec styles, navigation et notes.                                             |
| `LayoutSlideAuto.astro` | Présentation en boucle avec avance automatique, configurée à 20 secondes.                              |
| `LayoutSyllabus.astro`  | Document continu avec sommaire, notes visibles et impression.                                          |

Une page de présentation assemble des composants dans l’ordre souhaité :

```astro
---
import Layout from '@layouts/LayoutSlides.astro'
---

<Layout title="Introduction" lang="fr">
  <FrIntroAccessibility />
  <FrIntroWho />
</Layout>
```

Reveal.js affiche les `<section>` comme des diapositives ; des sections imbriquées permettent une navigation verticale. Les `<aside class="notes">` contiennent les notes de présentation.

Le syllabus réutilise les composants de contenu dans `LayoutSyllabus`. Ce layout adapte notamment les niveaux de titre, prépare le sommaire et remplace les vidéos intégrées par des liens. Pour modifier le contenu d’une slide partagée, modifier son composant. Pour modifier l’ordre ou la sélection des slides, vérifier **les deux pages**, présentation et syllabus : leurs listes sont actuellement définies séparément pour l’introduction.

## Les langues

`src/i18n/config.ts` déclare `fr`, `en` et `nl`, avec le français par défaut. Le réglage `prefixDefaultLocale` est absent : Astro utilise donc son comportement par défaut, sans préfixe pour le français. La documentation est exposée à `/docs` et `/docs/projet`. Les autres langues utilisent `/en/` et `/nl/`.

Les rôles se répartissent ainsi :

- `src/pages/fr/`, `en/`, `nl/` définissent les URL par langue.
- `src/components/fr/`, `en/`, `nl/` contiennent les contenus pédagogiques correspondants.
- `src/i18n/ui.ts` contient les traductions de l’interface.
- `src/i18n/utils.ts` fournit notamment `useTranslations(lang)` et la sélection d’une langue prise en charge.
- `src/i18n/client.ts` participe à la traduction de l’interface dans le navigateur.

Créer une page française ne crée pas automatiquement ses versions anglaise et néerlandaise. L’accueil `/` est une page particulière : en développement, il peut tenir compte de la langue préférée reçue par Astro ; la version construite reste statique et adapte aussi l’affichage dans le navigateur.

## Les images, styles et données

### Images et fichiers publics

Les images dans `src/assets/` sont importées depuis les composants. Exemple :

```astro
---
import Jim from '@assets/img/jim.png'
---

<img src={Jim.src} width={Jim.width} height={Jim.height} alt="Jim" />
```

Un fichier `public/robots.txt` est servi à `/robots.txt` en local avec `base: '/'`. Il est copié sans transformation lors de la construction. Les dossiers `src/assets/` et `public/` répondent donc à des usages différents.

### Styles

Les layouts importent les styles communs depuis `src/assets/css/`. Les présentations chargent aussi les styles Reveal.js et les thèmes AnySurfer. Un bloc `<style>` dans un composant permet des styles limités à ce composant ; un changement dans une feuille commune peut affecter de nombreuses pages. Voir le [guide des styles Astro](https://docs.astro.build/en/guides/styling/).

### Données JSON

`src/data/training-pages.json` sert notamment au catalogue des formations affiché sur l’accueil. Les fichiers `*-training-resources.json` regroupent des ressources de formation. Par exemple, `src/pages/fr/training/intro.astro` importe `intro-training-resources.json` pour afficher articles, applications et signets.

Ajouter une entrée dans un JSON ne crée pas de route : il faut aussi une page correspondante dans `src/pages/`.

## La documentation en développement

La **Content Collection** `docs`, déclarée dans `src/content.config.ts`, charge les fichiers Markdown de `src/docs/` avec le loader `glob()`. Son schéma Zod valide les métadonnées et fournit les types TypeScript. La page `src/dev/docs.astro` utilise `getCollection('docs')` pour la navigation et `render()` pour afficher le guide choisi. Voir le [guide officiel des Content Collections](https://docs.astro.build/en/guides/content-collections/). Une seule route `/docs/[...slug]` est injectée en développement. Le paramètre `slug` sélectionne le guide ; son absence affiche l’index à `/docs`.

| URL locale            | Contenu                                         |
| --------------------- | ----------------------------------------------- |
| `/docs`               | Index et navigation vers tous les guides        |
| `/docs/prerequisites` | Installation et prérequis                       |
| `/docs/installation`  | Récupérer, installer et mettre à jour le projet |
| `/docs/projet`        | Fonctionnement du projet                        |

Chaque guide commence par des métadonnées YAML, appelées **frontmatter**. Le titre et la clé de traduction sont obligatoires :

```yaml
---
title: Mon nouveau guide
slug: mon-guide
translationKey: mon-guide
lang: fr
order: 3
---
```

Pour ajouter un guide, créer simplement son fichier `.md` dans `src/docs/`. Il apparaît dans la navigation et devient accessible à `/docs/mon-guide`, sans modifier la configuration ni créer une page Astro supplémentaire. Ne pas ajouter de champ `layout` : la page commune fournit déjà le layout.

Le champ `slug` est facultatif : sans lui, le loader génère un identifiant normalisé à partir du chemin du fichier. Avec un `slug` explicite, celui-ci devient l’identifiant `id` de l’entrée et son chemin sous `/docs/`. Les sous-dossiers sont pris en charge. Les identifiants doivent être uniques ; Astro signale les collisions. Un slug explicite accepte les lettres non accentuées, chiffres, tirets, underscores et points internes aux segments, séparés par `/`. Le schéma exige un `title` non vide et valide `order` comme un entier (0 par défaut). La navigation trie les guides par `order`, puis par identifiant.

La navigation indique le guide actif et propose les guides précédent et suivant. Un slug inconnu renvoie une réponse HTTP 404. Le paramètre `[...slug]` permet à une seule route de couvrir l’index et les chemins de guides, y compris dans des sous-dossiers. `prerender: false` permet de sélectionner le guide à chaque requête en développement, sans `getStaticPaths()`.

Le layout dédié `src/layouts/LayoutDocs.astro` affiche le menu des guides, une zone de lecture blanche et la navigation entre les documents. Sur petit écran, le menu passe au-dessus du contenu.

Chaque traduction possède son propre fichier Markdown. Le champ `lang` indique `fr`, `en` ou `nl` ; `translationKey` relie les trois versions du même guide. Par exemple :

```yaml
---
title: Mon nouveau guide
slug: mon-guide
lang: fr
translationKey: mon-guide
order: 3
---
```

La version anglaise peut utiliser `slug: en/mon-guide`, `lang: en` et le même `translationKey: mon-guide`. La version néerlandaise utilise `nl/mon-guide` et `lang: nl`. Le champ `lang` vaut `fr` par défaut ; `translationKey` est obligatoire et doit être unique pour chaque langue. Le sélecteur ouvre la traduction correspondante et conserve le guide consulté. Le menu et les liens précédent/suivant affichent seulement les guides de la langue choisie. Les libellés de l’interface sont définis dans `src/i18n/docs.ts` et l’attribut HTML `lang` suit la langue du document.

L’index français est à `/docs`, l’anglais à `/docs?lang=en` et le néerlandais à `/docs?lang=nl`. Par exemple, les traductions de ce guide sont accessibles à `/docs/en/projet` et `/docs/nl/projet`. Ces chemins restent sous la route de développement unique et sont indépendants des préfixes i18n des pages de formation.

Ces routes restent absentes de `npm run build` et de `npm run preview`, car leur injection est réservée à la commande `dev`.

## Les commandes et le déploiement

### Construire un lien compatible avec GitHub Pages

Le site peut être publié sous un préfixe de dépôt. Les pages existantes utilisent cette convention :

```astro
---
const base = import.meta.env.BASE_URL.replace(/\/$/, '')
---

<a href={`${base}/fr/intro/`}>Présentation d’introduction</a>
```

Cela produit `/fr/intro/` à la racine ou, par exemple, `/nom-du-depot/fr/intro/` lorsque `base` contient le nom du dépôt.

Exécuter ces commandes à la racine du projet. `package.json` exige Node.js **22.12.0 ou plus récent**.

| Commande                      | Effet                                                     |
| ----------------------------- | --------------------------------------------------------- |
| `npm ci`                      | Installer les dépendances selon `package-lock.json`.      |
| `npm run astro -- dev status` | Afficher l’état et l’adresse du serveur.                  |
| `npm run astro -- dev logs`   | Consulter les journaux du serveur.                        |
| `npm run astro -- dev stop`   | Arrêter le serveur de développement.                      |
| `npm run build`               | Générer le site de production dans `dist/`.               |
| `npm run preview`             | Servir localement la dernière construction de production. |
| `npm run format:check`        | Vérifier le formatage avec Prettier.                      |
| `npm run format`              | Reformater les fichiers pris en charge du projet.         |

Le port habituel est `4321`. S’il est occupé, Astro peut choisir un autre port : utiliser l’adresse indiquée au démarrage ou par `dev status`.

`npm run preview` ne reconstruit pas les sources. Après une modification à vérifier en production, relancer d’abord `npm run build`.

Le workflow `.github/workflows/deploy.yml` construit et publie le site sur GitHub Pages lors d’un push sur `main`, ou d’un lancement manuel sur cette branche. Il définit `DEPLOY_TARGET=github-pages`. La configuration utilise alors `GITHUB_REPOSITORY` pour calculer `site` et `base`. En dehors de ce mode, elle accepte `SITE_URL` et `BASE_PATH`.
